# App icon & favicon (S-10) Implementation Plan

## Overview

Add a cohesive 10xCards app icon generated by the agent in Phase 1, export it to the standard favicon/touch-icon formats, and wire browser metadata in `Layout.astro` plus a minimal `site.webmanifest`. No application logic changes; branding only.

## Current State Analysis

- `src/layouts/Layout.astro` already references `/favicon.png` (line 20) but **`public/` has no favicon files** — only `.assetsignore`. Browsers get a missing asset.
- Brand text is plain **"10xCards"** in `AppTopbar.astro` — no logo image; favicon is the only visual mark in the tab bar.
- Paper theme tokens in `src/styles/global.css` (`.paper-theme`): warm background `oklch(0.98 0.01 90)`, primary green `oklch(0.38 0.08 155)`, fonts Instrument Serif + DM Sans.
- Roadmap S-10 prerequisites (S-08 paper UI) are **done** — icon should match paper palette, not legacy cosmic gradient.

## Desired End State

- Tab bar shows a readable favicon on light and dark browser chrome.
- iOS/Android "Add to Home Screen" uses `apple-touch-icon.png`.
- `site.webmanifest` provides `name`, `short_name`, `theme_color`, and icon entries for install hints (no service worker).
- Assets live in `public/` and deploy with the Worker static bundle.

Verification: hard-refresh `/`, confirm favicon in tab; DevTools → Application → Manifest shows valid manifest; add-to-homescreen preview (or iOS simulator) shows the touch icon.

### Key Discoveries:

- `Layout.astro` is the single `<head>` entry point for all pages — one file to update.
- Astro serves `public/` at site root — paths are `/favicon.png`, not `/public/favicon.png`.
- `.ico` is still requested by some browsers as fallback — include `favicon.ico` per user decision.

## What We're NOT Doing

- PWA service worker or offline caching.
- Logo image in `AppTopbar` (text brand stays).
- Animated favicon or dark-mode alternate icons.
- 192×512 icon set beyond what's needed for manifest MVP.
- Automated image pipeline in CI.

## Implementation Approach

Two phases: (1) generate and export assets with agent image generation + manual resize/conversion; (2) wire HTML head tags and `site.webmanifest`. Keep the icon motif simple for 16×16 legibility — stacked flashcards on warm paper background with primary green accent.

## Critical Implementation Details

**Small-size legibility:** Generate at 512×512 or 1024×1024, then downscale to 32×32 and verify the stack silhouette remains recognizable. If the 32×32 preview is muddy, simplify (fewer cards, thicker outlines, no fine text).

**theme_color:** Use the paper primary green, approximated as `#3d6b52` (from `oklch(0.38 0.08 155)`). **background_color** in manifest: warm paper `#faf8f4` (from `oklch(0.98 0.01 90)`).

## Phase 1: Generate icon assets

### Overview

Agent generates 2–3 icon variants, picks the most legible at small sizes, exports `favicon.png` (32×32), `favicon.ico` (multi-size 16+32), and `apple-touch-icon.png` (180×180).

### Changes Required:

#### 1. Image generation prompt

**File**: (process only — no source file)

**Intent**: Produce icon candidates aligned with paper theme and flashcard metaphor.

**Contract**: Prompt must specify:
- Motif: stacked flashcards / study cards (2–3 cards, slight offset)
- Palette: warm off-white paper background, forest-green accent (`oklch(0.38 0.08 155)`), no cosmic gradient
- Style: flat or soft minimal vector; no tiny text; works at 32×32
- Format: square, no rounded corners baked in (OS applies mask)
- Generate at least **2 variants** before selecting winner

#### 2. Export resized assets to public/

**File**: `public/favicon.png`, `public/favicon.ico`, `public/apple-touch-icon.png`

**Intent**: Commit production-ready static assets at paths already expected by layout conventions.

**Contract**:
- `favicon.png` — 32×32 PNG
- `apple-touch-icon.png` — 180×180 PNG
- `favicon.ico` — contains 16×16 and 32×32 layers (convert from selected PNG via ImageMagick, sharp CLI, or equivalent one-off tool)
- Source master kept only if useful; committed files are the three above

### Success Criteria:

#### Automated Verification:

- Files exist: `public/favicon.png`, `public/favicon.ico`, `public/apple-touch-icon.png`
- Build passes: `npm run build`
- Lint passes: `npm run lint`

#### Manual Verification:

- Open `public/favicon.png` at 32×32 — card stack silhouette is recognizable
- `apple-touch-icon.png` looks crisp at 180×180 on warm paper background
- Selected variant matches paper theme (green accent, warm paper, not cosmic dark)

**Implementation Note**: Pause after Phase 1 for human approval of the chosen icon before wiring head tags in Phase 2.

## Phase 2: Wire head metadata & manifest

### Overview

Update `Layout.astro` with complete icon links and add `public/site.webmanifest` for install metadata.

### Changes Required:

#### 1. Favicon and touch icon links

**File**: `src/layouts/Layout.astro`

**Intent**: Browsers and mobile OSes discover all icon formats from the shared layout head.

**Contract**:
- Keep or update `rel="icon"` for PNG (`/favicon.png`, `sizes="32x32"`)
- Add `rel="icon"` for ICO (`/favicon.ico`, `sizes="any"`)
- Add `rel="apple-touch-icon"` → `/apple-touch-icon.png`
- Add `rel="manifest"` → `/site.webmanifest`
- Optional: `meta name="theme-color"` matching manifest `theme_color`

#### 2. Web app manifest

**File**: `public/site.webmanifest`

**Intent**: Minimal install metadata without PWA scope.

**Contract** JSON fields:
- `name`: `"10xCards"`
- `short_name`: `"10xCards"`
- `theme_color`: `"#3d6b52"`
- `background_color`: `"#faf8f4"`
- `display`: `"standalone"`
- `start_url`: `"/"`
- `icons`: at minimum 180×180 (`apple-touch-icon.png`) and 32×32 (`favicon.png`) with correct `sizes` and `type`

### Success Criteria:

#### Automated Verification:

- `npm run build`
- `npm run lint`

#### Manual Verification:

- Hard-refresh `/` — favicon visible in browser tab (Chrome, Firefox, or Edge)
- DevTools → Application → Manifest — no errors; `theme_color` and icons listed
- Mobile or responsive mode: "Add to Home Screen" shows correct icon (or iOS Add to Home Screen preview)
- No regression on any route (dashboard, auth, review) — layout head unchanged aside from icon links

## Testing Strategy

### Unit Tests:

- None required — static assets and HTML meta only.

### Integration Tests:

- None required.

### Manual Testing Steps:

1. `npm run dev` → open `/` → confirm favicon in tab.
2. Open `/dashboard` (authenticated) — same favicon.
3. DevTools → Application → Manifest — validate JSON and icon URLs return 200.
4. Zoom favicon to 16×16 in image viewer — still recognizable.

## Performance Considerations

Negligible — three small static files (<50 KB total). No runtime cost.

## Migration Notes

No data migration. First deploy after merge replaces missing/broken favicon with new assets. Browsers may cache old favicon — hard refresh or cache-bust only if an old broken icon was cached (unlikely since file was missing).
